核心設計問題分析
================================================================================

【問題根源 1】架構混亂

系統設計中存在兩個獨立系統:

1. error_book (題目追蹤系統)
   用途: 跟蹤學生做過的錯題
   特點: 與題庫 (pack_questions) 關聯
   字段: question_id, status, last_attempted_at
   功能: 掌握度追蹤、間隔重複

2. backpack_notes (筆記系統)
   用途: 儲存學習筆記
   特點: 自由格式，不與題庫關聯
   字段: question (文本), canonical_skill, note_md
   功能: 筆記保存、分享

當前實現誤將「詳解卡 → backpack」，應為「詳解卡 → error_book + backpack」

【問題根源 2】信息缺失

ExplainCard 缺少 question_id，導致無法呼叫 error_book API:
├─ 輸入: inputText (題幹字符串)
├─ 處理: 生成詳解
└─ 輸出: 詳解 Markdown
    ✗ 缺失: 原始題目 ID

解決方案:
├─ 方案 A: 修改 ExplainCard 的輸入，加入 question_id (推薦)
└─ 方案 B: 允許 /api/error-book 接受 question 文本作為備用

【問題根源 3】流程設計缺陷

按鈕文案「加入錯題本」誤導用戶期望:
├─ 用戶期望: 將詳解內容加入錯題本
├─ 實際行為: 將詳解內容加入 backpack_notes
└─ 結果: 錯題本分頁無法展示
